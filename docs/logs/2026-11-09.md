## 2026-11-09 下午/晚上：远程监看联调

### 目标
- 功能③：手机通过网络远程实时监看。

### 方案
- 当前无 WiFi 模块（板载 WIRELESS 是 NRF24L01，不是 WiFi；ATK MODULE 接口可插 ATK-ESP8266）。
- 采用 PC 中继：STM32 USART1 → CH340/COM22 → PC `relay_server.py` → JPEG → 手机 Web APP。
- 手机端不用 Android Studio，用 JPEG 轮询 Web APP（兼容所有手机浏览器）。

### 关键问题与解决
1. **DTR/RTS 一键下载电路**：pyserial 打开 COM22 会拉 DTR/RTS，触发板载一键下载，复位进 Bootloader。解决：打开后立即 `dtr=False; rts=False`。
2. **MJPEG `<img>` 手机不兼容**：手机页面一直“重新连接”。解决：Web APP 改为 `/snapshot.jpg` JPEG 轮询（5fps）。
3. **URL 查询参数 404**：服务器用 `self.path` 精确匹配，`/snapshot.jpg?t=...` 404。解决：`urlparse(self.path).path`。
4. **UART 错帧/彩色横条**：1.5M 下丢字节 + 载荷内假帧头。解决：
   - 帧协议 v2 加 16 位累加和，PC 端校验失败丢帧；
   - PC 串口读帧与 JPEG 编码分线程（生产者/消费者），避免编码阻塞导致驱动缓冲溢出。
5. **帧率/清晰度取舍**：
   - 160×120 RGB332 1.5M → 4.3fps，但手机上很糊；
   - 240×180 1.5M → 2.3fps；2M → 1.5fps（CH340 丢字节）；
   - 200×150 1.5M → 3.1fps（未校验）/2.6fps（校验后）；
   - 200×150 1M → 2.3fps（UART 时间 300ms 限制）；
   - **192×144 RGB332 1.5M → 3.0fps，最终选择**。

### 最终结果
- 本地 LCD：320×240，约 9–10fps（与远程并行），偶发彩色闪帧。
- 远端：192×144 RGB332，3.0fps，校验丢错帧，画面干净。
- 手机：`http://192.168.1.243:8000/`，Web APP 实测可看。
- 证据：`docs/deliverables/pet-monitor-remote-v1.hex`、`remote-snapshot-192x144.jpg`。
- 协议：`docs/reference/frame-protocol.md`。
- 使用说明：`pc-tools/README.md`。
