# flow —— 嵌入式固件五阶段流程

开工前必读。每阶段有明确的进入条件、产出与放行标准;结论写入 `HANDOFF.md`。

| 阶段 | 文档 | 进入条件 | 产出 | 放行标准 |
| --- | --- | --- | --- | --- |
| 1 需求 | `01-requirements.md` | 目标平台与验收标准已确认 | 需求条目(功能/时序/资源/接口) | 每条可验证,无歧义 |
| 2 选型 | `02-platform-select.md` | 需求条目已定稿 | `toolchains.json` 目标条目 + HAL 层级结论 | 选型依据充分,迁移成本已评估 |
| 3 编码 | `03-coding.md` | 选型已确认 | `fw/` 与 `drivers/` 代码 | 宿主侧编译 0 error;静态检查通过 |
| 4 静态检查 | `04-static-check.md` | 编码完成 | 检查报告 | 告警逐条有结论(修/豁免) |
| 5 烧录与 HIL | `05-flash-hil.md` | 静态检查放行 | 烧录记录 + HIL 观测记录 | 观测项逐条通过;未跑项如实标注 |

红线:阶段 5 未跑不声称"已验证通过";`pcb-design-starter` 侧文件只读不改。
