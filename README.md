## 2. 系统方案

**为什么不是 OV2640 / USB 摄像头**：F103 无 DCMI 摄像头接口、USB 只有从机模式，两者硬件上不可行；串口摄像头帧率过低。选用 **OV7670 带 AL422 FIFO 模块**：FIFO 按像素时钟实时缓存整帧，MCU 用 GPIO 异步读出，解决高速像素流与主控读取速率不匹配的问题（这是报告方案论证的核心亮点）。

**两条数据链路**：

```
本地链路：OV7670 ─DVP→ AL422 FIFO ─GPIO读取→ STM32F103 ─FSMC→ 2.8寸LCD 实时显示
远程链路：FIFO读帧时2×2降采样 → QQVGA缓冲(RAM) → jpge软件JPEG编码
         → USART2@460800/921600 → ESP8266(TCP服务器) ─WiFi→ 安卓APP解码显示
```

**指标目标**：本地显示 QVGA ≥10fps；远程监看 QQVGA ≥3fps；端到端延迟 <1s。

## 7. 风险与保底预案

| 风险 | 对策 |
|---|---|
| 花屏/颜色错 | 按排查清单：字节序对调 → VSYNC 极性 → WRST/RRST 时序 → 换短杜邦线 → 换备用模块 |
| 远程帧率低 | 降 JPEG 质量 / 用 QQVGA / 波特率拉满 921600 |
| ESP8266 调不通 | 换 ESP-01S 重刷 AT 固件；仍不行先用 PC 上位机脚本顶替演示，APP 后补 |
| RAM 不够（64KB 上限） | 降 JPEG 质量、复用缓冲、裁掉不用的外设缓冲 |
| 时间崩盘 | 阶段 2 完成即保底功能①②；③按上述逐级降级 |
| 答辩现场网络翻车 | 播放备用演示视频（阶段 2、阶段 4 各录一份） |
